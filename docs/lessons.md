# 踩坑实录：10 个坑与解法

> 绿联 DH4300 Plus + UGOS Pro，2026-10 实测环境。每条坑都有实锤证据，不是玄学。

---

## 1. Docker 镜像拉不动

**现象**：`docker pull` 官方源超时/失败。
**解法**：镜像源换 `docker.m.daocloud.io`（前缀替换法：`docker.m.daocloud.io/jellyfin/jellyfin:10.10.7`）。

## 2. 应用中心应用「装好了」但起不来

**现象**：应用中心 Jellyfin 安装成功，桌面图标双击无窗口，端口无监听。
**排查教训**：先确认应用的真实端口（UGOS 应用常用随机端口），`8096 无监听` ≠ 应用崩了。用应用详情页确认端口，别靠猜。
**附带坑**：安装应用时旧服务还占着端口 → 应用启动即崩 → 崩溃态不会自愈，需要手动重启应用。

## 3. Jellyfin 12.x 向导 API 变更 → 无账号锁死

**现象**：用 10.x 时代的 `POST /Startup/User {Name, Pw}` 建号返回 404/500，但 `POST /Startup/Complete` 仍然 204 → 向导被标记完成但系统里没有账号 → 全 API 401 锁死。
**解法**：锁死后重置 = 删配置目录重启；**正确姿势**：新版本先查 `/openapi` 确认端点，或者干脆固定用 10.10.x LTS（脚本见 [jellyfin/](../jellyfin/)）。
**教训**：向导多步 API 操作**不要跳步**——Complete 之前必须确认账号创建成功。

## 4. Docker bridge 容器吃不到宿主机 IPv6

**现象**：宿主机有公网 v6，bridge 容器内 `v6(false)`。
**原因**：Docker 默认网桥 v4-only，v6 需显式开启且配置繁琐。
**解法**：`network_mode: host`——容器直接用宿主机网络栈，v4/v6 全继承。
**代价**：端口由容器自己管理，注意冲突。对单机自用场景零代价。

## 5. bridge 模式 Tailscale 打洞永远失败

**现象**：`tailscale ping` 永远 `via DERP(xxx) 300ms+`，`direct connection not established`。
**根因**：bridge 容器的 UDP 经 Docker NAT 转换，端点信息失真，打洞成功率暴跌。
**解法**：Tailscale 容器改 host 模式（见 [tailscale/compose-host.yml](../tailscale/compose-host.yml)）。**状态目录保留则无需重新授权**。

## 6. 机房拦截 UDP 入站（安全组开了也没用）

**现象**：云服务器安全组已放行 UDP 41641/3478，外部 `tcpdump` 仍 0 包到达（换任意未放行端口对照后实锤：**机房上游层面拦截，安全组形同虚设**）。
**解法**：换 UDP 未被封的机器（多数国内小厂/部分线路默认拦 UDP，购买前问清）。
**教训**：`tcpdump + 对照端口` 是分锅利器——先证明「包没到」，再谈「谁拦的」。

## 7. Windows curl (schannel) 对自签 TLS 假阴性

**现象**：`curl -k https://IP:8443` 秒断（000），但 `openssl s_client` 和 Go 客户端握手正常。
**根因**：Windows curl 用 schannel TLS 栈，对自签证书的兼容性差，报 `SEC_E_INVALID_TOKEN`。
**教训**：**curl 的「000」≠ 不通**。换 `openssl s_client -servername` 交叉验证再下结论。Tailscale 客户端是 Go 栈，不受影响。

## 8. 云服务器访问自己的公网 IP（hairpin）被拦

**现象**：云机器连接 `自己的公网IP:8443` 失败，但外部连接正常。
**解法**：`/etc/hosts` 加 `公网IP域名映射到 127.0.0.1`——本机回环访问自己的服务。
**适用**：所有「服务器要访问自己公网地址」的场景。

## 9. 未备案域名的 SNI 限制

**现象**：未备案域名解析到国内服务器，80/443 的 Web 服务有被拦风险。
**解法**：非标准端口（8443）+ DNS-01 签证书（不碰 80/443）。Tailscale 自建 DERP 场景下配合 `InsecureForTests`（自签证书）可彻底绕开证书签发。
**注意**：客户端走 IP 字段连接时 SNI 仍会发送 HostName，derper 按证书匹配校验，需保持一致。

## 10. 「没找到」≠「不存在」

**现象**：排查 NAS 上某服务「崩了」——端口扫不到、图标点不开。实际上服务活着，只是端口是随机分配的 + 自动化点不中图标。
**教训**：下结论前先穷尽证据：问当事人（用户自己看得见界面）、扫全端口、看服务日志。**自动化工具的盲区不等于系统的故障。**

## 附：UGOS 文件管理 UI 自动化的现实

右键菜单/对话框的 DOM 结构不稳定（菜单项无文本定位、按钮同名隐藏、坐标漂移），Playwright 自动化成功率低。**结论：界面操作交给人工，命令行/API 交给脚本**——各干各擅长的。
